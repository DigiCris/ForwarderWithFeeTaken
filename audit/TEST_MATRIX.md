# Test matrix — Forwarder V3 (final): fee configuration and treasury cooling periods, fee overrides

Requirement → evidence across tools. Section numbers refer to the V3 request. The vault lifecycle (V2) and the V1
logic keep their matrices ([TEST_MATRIX_V2.md](TEST_MATRIX_V2.md), [TEST_MATRIX_V1.md](TEST_MATRIX_V1.md)); their suites
run unchanged or adapted to the delayed API as regression (report sections F and H).

Legend — **U** unit (`test/ForwarderFeeChange.t.sol`, `test/ForwarderTreasuryChange.t.sol`,
`test/ForwarderFeeOverride.t.sol`, adapted `test/Forwarder.t.sol` and V2 suites), **F** fuzz
(`test/ForwarderV3Fuzz.t.sol`, 50,000 runs in the deep campaign), **I** Foundry invariant
(`test/ForwarderV3Invariant.t.sol` + `test/invariants/FeeTreasuryHandler.sol`, 500,000 calls each), **E** Echidna
property (`echidna/ForwarderV3Echidna.sol`), **C** Certora rule/invariant (`certora/specs/ForwarderV3.spec`), **K** Base
fork (`test/fork/ForkTestBase.sol`, also run against the deployed address), **M** mutant killed
(`audit/scripts/mutation_v3.py`, `audit/raw/v3/mutation/`).
